# 다음에 할 일 — 실사용까지 가는 순서

**개발은 끝났습니다.** 34화면 · 96개 테스트 통과. 여기부터는 **값을 넣고 연결하는 일**입니다.

순서가 중요합니다. 앞 단계가 안 되면 뒤가 의미 없는 것들만 순서대로 놓았습니다.

## 0단계 — 오늘, 5분 (대표)

### 구글 시트 공유 범위를 「제한됨」으로

지금 링크를 가진 누구나 편집할 수 있습니다. 급여·부채·거래처가 그 시트에 있습니다.

- 버전 기록도 확인 — 외부 편집 흔적이 있으면 이관 기준 시점을 그 이전으로 잡아야 합니다

이거 하나만 해두시면 나머지는 급하지 않습니다.

## 1단계 — 배포 (대표 30분 + 재무 15분)

### ① 구글 OAuth 클라이언트 (대표, 10분)

[Cloud Console](https://console.cloud.google.com/apis/credentials) → OAuth 클라이언트 ID → 웹 애플리케이션

| 항목         | 값                                            |
| ------------ | --------------------------------------------- |
| 리디렉션 URI | `https://<배포주소>/api/auth/google/callback` |
| 동의 화면    | **내부(Internal)** — 워크스페이스 구성원만    |

### ② DB 고르기 (대표 판단 · 재무 실행)

`docs/erp-deploy.md`에 5종 비교표가 있습니다. 판단 기준은 셋뿐입니다.

- **국내 보관이 요건인가** → 예: AWS RDS 서울 / 아니오: 도쿄 리전으로 충분 (지연 30~40ms)
- **PostgreSQL로 갈 것인가** → 사양서 권고안. 스키마 한 파일이라 dialect 교체 반나절
- **지금 돈 안 쓰고 시작** → TiDB Cloud (무료 · MySQL 호환 · 코드 변경 0)

연결 문자열은 **채팅에 붙이지 마시고** Vercel 환경변수에 직접 넣으신 뒤 "넣었다"고만 알려주십시오.

### ③ Vercel 환경변수

**최소 5개 — 이것만 있으면 로그인하고 화면이 뜹니다.**

| 이름                                        | 없으면                                   |
| ------------------------------------------- | ---------------------------------------- |
| `GOOGLE_CLIENT_ID` · `GOOGLE_CLIENT_SECRET` | 로그인 불가                              |
| `SESSION_SECRET`                            | 로그인 불가 (`openssl rand -base64 48`)  |
| `ERP_ALLOWED_DOMAIN` = `dinostudio.kr`      | **아무도 못 들어옴** (기본값이 「닫힘」) |
| `ERP_ROLE_MAP` = `{"대표이메일":"대표"}`    | 「역할 미지정」으로 막힘                 |
| `DATABASE_URL`                              | 시드가 메모리에 올라가 재시작 시 초기화  |

**나중에 켜도 되는 것** — 슬랙(`SLACK_*`) · AI(`ANTHROPIC_API_KEY`) · 증빙 파일(`ERP_S3_*`).
없어도 시스템은 돌아갑니다. 증빙은 드라이브 링크로, 알림은 알림함으로 대체됩니다.

### ④ 적재 (재무)

```
pnpm db:push      # 테이블 생성
pnpm erp:seed     # 시드 27건 + 일계 7행 + V1~V8 검증 리포트
```

리포트에서 **V1 · V7 · V8이 불일치로 나오는 게 정상**입니다 — 고쳐서 통과시키는 항목이 아니라
그대로 노출하는 항목입니다.

### ⑤ 확인

`https://<배포주소>/erp` → 구글 로그인 → 현금 현황에서 **P0 부족액 −272,110** 이 나오면 성공.

## 2단계 — 첫 주 실사용 (재무 중심)

배포가 끝나면 **시트를 계속 쓰셔도 됩니다.** 전환일은 나중에 정하면 됩니다.
먼저 이 시스템에서 아래 셋만 하십시오.

### ① 판정 대기 8건 정리 (재무 + 입력자)

가장 큰 막힘입니다. **이것만 풀려도 08/26부터 종료 잔액이 다시 이어집니다.**

| 무엇                                               | 어떻게                        |
| -------------------------------------------------- | ----------------------------- |
| 적요칸 금액 5건 (급여 2 · 부가세 2 · 디에스브릿지) | 금액 칸에 원 단위로 다시 넣기 |
| 항목명 없는 30,000,000 (MBC)                       | 항목명과 방향(수입/지출) 확정 |
| 중복 의심 7,500,000 (셀릿)                         | 08/22 건과 같은 건인지 확인   |

화면: 집행원장 → 코드 클릭 → 금액·항목 수정 → 저장

### ② 급여 실액 넣기 (대표)

기준값 화면에서 `payroll_monthly_actual` 한 줄. 넣는 순간 번레이트 산출 조건이 하나 풀립니다.

### ③ 매일 지출을 이 시스템에 입력 (입력자)

집행원장 또는 현금 현황에서 「직접 추가」. 시트에도 쓰시되 **판단은 이 시스템 숫자로** 하십시오.

## 3단계 — 연동 켜기 (선택 · 재무 30분)

### 슬랙 (§11.1)

1. 슬랙 앱 → Event Subscriptions → `https://<배포주소>/api/integrations/slack/events`
2. `message.channels` 이벤트 구독 · 대상 채널에 봇 초대
3. 환경변수 `SLACK_SIGNING_SECRET` · `SLACK_EXPENSE_CHANNELS`(채널 ID 두 개)

켜면 #지출-네트워크-사업부 봇 메시지가 검수함에 자동으로 쌓입니다.
**승인은 여전히 이 시스템 안에서만** 합니다.

### AI 파서 — `ANTHROPIC_API_KEY`

#지출-ip-사업부의 수기 메시지를 읽습니다. 정형 메시지는 규칙 파서가 처리하므로
AI는 실패한 것만 받습니다. 모르는 값은 추정하지 않고 「확인 필요」로 세웁니다.

### 알림 도착지 (B7)

`SLACK_BOT_TOKEN` + `SLACK_NOTIFY_CHANNEL`. 지금은 알림함에만 쌓입니다.

## 4단계 — 시트 전환 (하루, 30분)

실사용이 손에 익으면 전환일을 하루 정하십시오.

1. `/erp` → 기준·통제 → **시트 이관**
2. 전환 시작일 이후 구간을 헤더 줄까지 복사해서 붙여넣기
3. **미리보기** — 무엇이 판정 대기로 떨어지는지 먼저 확인
4. 판정 대기가 많으면 시트에서 고치고 다시 붙여넣기 (아직 저장 전)
5. 확인 · 적재 → 종합 현황에서 V1~V8 확인 → 대표·재무 서면 확인
6. 시트 사본을 `[동결] 데일리 현금흐름 ~YYYY-MM-DD` 로 만들고 보기 전용 전환

**전환 전까지 지켜주실 것 하나** — 금액을 적요 칸에 쓰지 마십시오. 금액 칸에 원 단위로.
지금 판정 대기 8건 중 5건이 이것 때문에 생겼습니다.

## 회의에서 정해주실 것 6가지

코드는 어느 쪽이든 맞출 수 있지만 **먼저 정하지 않으면 나중에 데이터를 고쳐야** 합니다.

1. **VAT 표기 기준** — IP는 (vat별도), 네트워크는 (VAT 포함). 전사 통일 vs 원장 분리 저장
2. **손익 귀속 기준일** — 착수일 / 최종 업로드일 / 지출 요청일
3. **성사 가능성 환산율** — 상/중/하를 확률로
4. **통과원가 계약 구조** — 중개면 예수금(부채), 원가 구조면 영업활동
5. **틱톡샵 정산 4가지** — 통화 · 매출 인식 시점 · 수수료 계정 · 총액/순액. **첫 정산 처리가 기준으로 굳습니다**
6. **08-27 미결 4건** — 카드 집행 기록 위치 / 영업·투자·재무 분리 시점 / 채권 메일링 범위 / 사업부 구분
