## A. 회계 정합성 — 회계사 관점 (16)

### A1 🔴 전표가 부가세를 분리하지 않는다 [개발]

`buildJournal`은 2줄 분개만 만든다 — 비용 전액 / 현금 전액.
`1450 부가세대급금`·`2130 예수부가세` 계정은 있는데 쓰이지 않는다.
**결과** 공급대가 전액이 비용으로 잡혀 **손익이 부가세만큼 과대계상**되고, 부가세 신고 시 매입세액을 원장에서 집계할 수 없다. 재무상태표의 부가세 계정은 영원히 0이다.
**고침** 과세 건은 3줄 분개로 — 비용(공급가액) / 부가세대급금(세액) / 현금(공급대가). 면세·불공제 건은 2줄 유지.
`근거` shared/erp/journal.ts:17, shared/erp/accounts.ts:45-46

### A2 🔴 원천징수 분개가 없다 [개발]

외주 사업소득 3.3%, 급여 근로소득세·4대보험을 예수금으로 잡지 않는다.
**결과** 지급액과 비용이 같아져 **예수금 부채가 누락**된다. 다음 달 납부할 돈이 재무제표에 안 보인다.
**고침** 지급 시 `비용 / 예수금 + 현금` 3줄 분개. 원천징수율을 계정별 기본값으로 둔다.
`근거` grep 결과 원천징수 관련 분개 로직 0건

### A3 🔴 자산 취득이 비용으로 나간다 [개발·대표]

자산대장이 없어 `취득 → 감가상각`이 없다.
**결과** 취득 월 손익이 급감하고 이후 월은 과대계상된다. 번레이트 계산에서도 자산 취득을 빼지만(§accounts.ts:145) **자산 계정으로 넘기지 않으므로 대차가 맞지 않는다.**
**고침** `assets` 테이블 + 정액법 월 감가상각 자동 전표. 기준금액(예: 1,000,000원) 이상만 자산화 — 기준은 [대표] 결정.

### A4 🟡 발생주의·현금주의 전환이 화면에만 있고 계산이 하나다 [개발]

`accrualDate`·`cashDate` 필드는 둘 다 있으나 손익·현금흐름이 같은 기준으로 계산된다.
**결과** 「집계 기준」을 바꿔도 숫자가 같거나, 한쪽이 틀린다.
**고침** 손익은 `accrualDate`, 현금흐름은 `cashDate` 를 축으로 분리. 프로토타입 `cf-basis` 셀렉트를 실제로 연결.

### A5 🟡 미지급금·미수금 대응이 자동이 아니다 [개발]

`2120 미지급금`은 카드 상계용으로만 쓰인다. 발생 후 지급까지의 채무가 원장에 남지 않는다.
**고침** 발생일 ≠ 지급일이면 발생 시 `비용/미지급금`, 지급 시 `미지급금/현금` 2단 전표.

### A6 🟡 대손 처리가 없다 [개발·대표]

채권이 회수 불능이 되어도 상태만 바뀌고 대손상각비 전표가 없다.
**고침** 연체일수 기준 대손충당금 설정률 + 확정 대손 전표. 설정률은 [대표] 결정.

### A7 🟡 선급비용·선수수익 이연이 없다 [개발]

연간 SaaS 결제, 선수금이 결제월에 전액 잡힌다.
**고침** 이연 시작·종료월을 받아 월할 배분 전표.

### A8 🟢 외화 거래를 원화로만 받는다 [개발]

해외 결제 건이 있는데(증빙 사유에서 확인) 통화·환율 필드가 없다.
**고침** `currency` · `fxRate` · `fxDate` 추가. 환산 차이는 외화환산손익으로.

### A9 🔴 시산표 검증이 화면에만 있고 저장 시 강제되지 않는다 [개발]

`buildJournal`이 항상 균형을 만들지만, 수동 전표나 향후 3줄 분개에서 깨질 수 있다.
**고침** `appendJournal` 저장 직전 차변합=대변합을 서버에서 단정. 안 맞으면 저장 자체를 거부.

### A10 🟡 계정과목에 결산 매핑이 없다 [개발]

31개 계정이 재무제표 어느 줄로 가는지가 코드에 흩어져 있다.
**고침** 계정 마스터에 `fsLine` 컬럼 — 재무제표 5종이 이 매핑만 보도록.

### A11 🟡 통과원가(pass-through)가 매출·매입 총액으로 잡힌다 [개발·세무]

광고 대행처럼 고객 예산을 대신 집행하는 건.
**결과** 매출이 부풀어 보인다 — 투자자에게 설명이 안 되는 숫자.
**고침** `isPassThrough` 플래그 + 순액 표시 옵션. 총액/순액 기준은 [세무] 확인.

### A12 🟢 전기 이월 잔액을 사람이 넣는다 [개발]

`30,000,000` 같은 시작 잔액이 설정값으로 들어간다.
**고침** 마감 시 다음 월 기초잔액을 자동 생성하고, 수동 입력은 이관 첫 달만 허용.

### A13 🟡 계정별 보조부가 없다 [개발]

계정과목 체계는 있으나 계정별 원장(총계정원장)이 없다.
**고침** 계정 클릭 → 그 계정의 차대변 명세 + 잔액 추이.

### A14 🟢 전표 번호가 UUID다 [개발]

감사·세무조정 시 사람이 참조할 수 없다.
**고침** `2026-08-0001` 형태 연월-순번. UUID는 내부 키로만.

### A15 🟡 부가세 신고 단위(과세기간)와 마감 단위(월)가 다르다 [개발]

월 마감은 있으나 분기 신고 단위 집계가 없다.
**고침** 과세기간(1~3월/4~6월…) 집계 화면 — 매출세액·매입세액·차감납부세액.

### A16 🟢 계정 변경 이력이 전표에 반영되지 않는다 [개발]

확정 후 계정을 바꾸면 `-R1` 수정본이 생기나, 기존 전표는 역분개된다(수정됨). 다만 **어느 전표가 어느 수정본에 대응하는지**를 화면에서 추적하기 어렵다.
**고침** 전표 화면에 `원본 · 역분개 · 재분개` 3열 대응 표시.

## B. 세무 (10)

### B1 🔴 매입세액 공제 대상 여부가 계정과목과 연동되지 않는다 [개발·세무]

증빙 종류로는 판정하지만(신규 구현), **접대비·비영업용 차량·면세사업 관련 매입은 적격증빙이 있어도 불공제**다.
**고침** 계정 마스터에 `vatDeductible` 컬럼. 접대비(6410) 등은 기본 불공제.

### B2 🟡 접대비 한도 관리가 없다 [개발·세무]

접대비는 수입금액 기준 한도를 넘으면 손금불산입이다.
**고침** 연 누적 접대비 대비 한도 표시. 한도식은 [세무] 확인.

### B3 🟡 기준금액·세율이 코드 상수다 [세무]

3만원 / 1만원 / 2% / 10% 를 `evidence.ts` 상수로 두었다.
**고침** 설정값으로 이동하고, 최초 1회 [세무] 확인 후 확정.

### B4 🟡 세금계산서 발행 관리가 없다 [개발]

받는 쪽(매입)만 있고 **우리가 발행해야 하는 세금계산서**가 없다.
**결과** 매출세액 신고 근거가 원장에 없다. 발행 누락 시 가산세.
**고침** 매출 건에 `발행 예정 / 발행 완료 / 미발행` 상태 + 발행기한(공급일 다음달 10일) 알림.

### B5 🟡 원천세 납부 기한 알림이 없다 [개발]

매월 10일 납부, 반기납부 특례 대상일 수도 있다.
**고침** 예수금 잔액 + 납부기한 D-day. 반기납부 여부는 [세무] 확인.

### B6 🟢 4대보험 사업주 부담분이 급여에 섞인다 [개발]

`6110 급여` 하나로 잡히면 사업주 부담분(비용)과 근로자 부담분(예수금)이 구분되지 않는다.
**고침** 급여 전표를 급여/사업주부담/예수금으로 3분할.

### B7 🟡 부가세 예수·대급 상계가 없다 [개발]

신고 시 매출세액−매입세액 차액만 납부하는데, 두 계정을 상계하는 전표가 없다.
**고침** 과세기간 마감 시 상계 전표 자동 생성 → 미지급세금.

### B8 🟢 증빙불비가산세는 「지출증명서류 합계표」 제출 대상과 연동해야 한다 [세무]

지금은 건별 계산만 한다.
**고침** 연간 합계 화면. 실제 신고 대상 범위는 [세무] 확인.

### B9 🟡 인건비 지급 대상 구분이 없다 [개발]

근로소득(급여) / 사업소득(3.3%) / 기타소득이 원천징수율과 신고서를 다르게 만든다.
**고침** 거래처 마스터에 `소득구분` — 프리랜서·직원 구분.

### B10 🟢 세무 신고 캘린더가 없다 [개발]

부가세(1·4·7·10월) · 원천세(매월) · 법인세(3월) · 지급명세서(2월) 등.
**고침** 신고 캘린더 + D-day 알림. 대표가 놓치면 가산세가 붙는 항목만 담는다.

## C. 자금 · 채권채무 (8)

### C1 🔴 예약런웨이에 미지급 예수금·세금이 빠져 있다 [개발]

승인 대기만 차감한다. **다음 달 납부할 부가세·원천세는 이미 확정된 유출**인데 안 보인다.
**고침** 예약런웨이 = 보유현금 − 승인대기 − 예수금 − 미지급세금 − 확정 차입 상환.

### C2 🟡 13주 자금계획이 채권 회수 확률을 반영하지 않는다 [개발·대표]

발행대기 127,600,000이 100% 들어온다고 가정한다.
**고침** 연체구간별 회수율 가중. 회수율은 [대표] 판단 + 실적 누적 후 갱신.

### C3 🟡 차입 상환 스케줄이 이자·원금으로 분리되지 않는다 [개발]

원금만 P1으로 잡힌다. 이자는 비용, 원금은 부채 감소 — 손익 영향이 다르다.
**고침** 상환 스케줄에 원금/이자 분리 + 자동 전표.

### C4 🟡 여신·한도 관리가 없다 [개발]

마이너스통장·카드 한도가 실질 유동성인데 보이지 않는다.
**고침** 한도·사용액·잔여한도. 현금 현황에 「즉시 동원 가능액」으로 합산 표시.

### C5 🟢 계좌별 잔액이 하나로 합쳐져 있다 [개발]

`1110 보통예금` 하나. 실제로는 여러 계좌일 것이다.
**고침** 계좌 마스터 + 계좌별 잔액. 대사(reconciliation)의 전제다.

### C6 🔴 은행 대사가 사람 눈에 의존한다 [개발·대표]

상단바의 「대사 차액 0」은 프로토타입 표시일 뿐 실제 대사 기능이 없다.
**고침** 계좌 거래내역 업로드(CSV) → 원장 자동 매칭 → 미매칭 건만 노출. 명세 제공 방식은 [대표] 결정.

### C7 🟡 채권 연령분석 구간이 고정이다 [개발]

**고침** 구간(30/60/90/90+)을 설정값으로. 업종에 따라 다르다.

### C8 🟢 지급 우선순위가 P0~P3 하나뿐이다 [개발]

같은 P0 안에서 무엇을 먼저 낼지가 없다.
**고침** 같은 등급 내 정렬 규칙(기한 → 연체이자 → 거래관계).

## D. 통제 · 감사 (8)

### D1 🟡 자기승인 차단이 생성자만 본다 [개발]

`entry.createdBy === actor.id` 만 막는다. 수정본(`-R1`)을 만든 사람은 승인할 수 있다.
**고침** 수정 이력에 등장한 모든 사람을 승인에서 제외.

### D2 🟡 승인 한도가 건별이다 [개발]

같은 거래처에 100만원씩 30건을 쪼개면 한도를 우회한다.
**고침** 동일 거래처·동일 주간 합계로 한도 재판정.

### D3 🟢 감사로그 조회 자체가 기록되지 않는 화면이 있다 [개발]

급여는 `recordSensitiveRead`가 있으나, 부채·계약 열람은 기록하지 않는다.
**고침** 민감 테이블 목록을 설정값으로 두고 일괄 적용.

### D4 🟡 마감 후 수정 차단이 cashDate 기준이다 [개발]

`requireWritable`은 `cashDate ?? accrualDate` 의 월만 본다. 발생월이 마감됐는데 지급월이 안 마감된 건은 통과한다.
**고침** 두 날짜 **모두** 검사.
`근거` server/erp/service.ts:1516

### D5 🟢 권한이 6역할 고정이다 [개발]

읽기 전용 감사·투자자 뷰가 없다.
**고침** `외부열람` 역할 — 금액 마스킹 + 다운로드 금지.

### D6 🟡 삭제가 없는 대신 취소가 있으나, 취소 사유 분류가 없다 [개발]

**고침** 취소 사유를 코드화(중복입력/오기재/거래취소) — 통계가 개선 근거가 된다.

### D7 🟢 세션이 12시간 고정이다 [개발]

급여 화면을 본 세션은 더 짧아야 한다.
**고침** 민감 화면 진입 시 재인증(step-up).

### D8 🟡 백업·복구 리허설을 한 번도 하지 않았다 [대표]

**고침** DB 붙인 직후 1회 복구 리허설. 「복구된다」는 확인 없이 백업은 백업이 아니다.

## E. 경영 판단 · 화면 — 대표 관점 (12)

### E1 🔴 첫 화면이 「그래서 지금 뭘 해야 하나」를 말하지 않는다 [개발]

현금흐름표가 첫 화면인데, 표를 읽어야 판단이 나온다.
**고침** 상단에 3줄 고정 — ①이번 주 부족액 ②오늘 결정해야 하는 건 ③기한 임박 3건.

### E2 🔴 런웨이가 개월 수로 안 보인다 [개발]

번레이트는 있으나 「몇 개월 남았나」가 한눈에 없다.
**고침** 최상단 KPI에 `런웨이 N.N개월` + 낙관/기본/보수 3안.

### E3 🟡 의사결정에 필요한 「이 건을 승인하면 런웨이가 며칠 줄어드는가」가 없다 [개발]

**고침** 승인 화면 각 행에 `런웨이 −N일` 표시. 이게 승인 판단의 실제 단위다.

### E4 🟡 프로젝트 수익성이 완료 후에만 보인다 [개발]

진행 중 프로젝트의 예상 마진이 없다.
**고침** 계약금액 − (기투입 + 잔여추정) = 예상마진. 잔여추정은 사람이 넣는다.

### E5 🟡 매출 집중도(고객 편중) 지표가 없다 [개발]

상위 1개 고객이 매출 40%면 그게 최대 리스크다.
**고침** 상위 고객 매출 비중 + HHI. 투자 실사에서 반드시 묻는 숫자.

### E6 🟢 목표 대비가 없다 [개발·대표]

예산 화면은 있으나 목표값이 비어 있다.
**고침** 월 매출·이익 목표 입력 → 달성률. 목표는 [대표] 입력.

### E7 🟡 인당 생산성이 없다 [개발]

**고침** 인당 매출·인당 이익 추이. 채용 판단의 근거.

### E8 🟢 채널·사업부 손익에 공통비 배부 기준이 화면에 안 보인다 [개발]

배부 화면은 있으나 기준이 결과와 함께 표시되지 않는다.
**고침** 손익 화면에 「이 숫자는 인원수 기준 배부」를 항상 병기.

### E9 🟡 알림이 알림함에만 쌓인다 [개발·대표]

대표가 시스템에 들어와야 본다 — 놓친다.
**고침** 슬랙 연동을 실제로 켠다. 도착지는 [대표] 결정(B7 미결).

### E10 🟢 모바일에서 승인이 어렵다 [개발]

반응형은 있으나 승인 흐름이 데스크톱 전제다.
**고침** 모바일 승인 전용 화면 — 건별 카드 + 스와이프 승인/보류.

### E11 🟡 내보내기가 탭 구분 텍스트 중심이다 [개발]

세무대리인은 엑셀 양식을 원한다.
**고침** 세무대리인 제출용 고정 양식(계정별 집계 + 증빙 목록) 1클릭.

### E12 🟢 「이 숫자를 믿을 수 있나」가 화면마다 다르게 표현된다 [개발]

지표 신뢰도 화면이 별도로 있다.
**고침** 각 화면 상단에 신뢰도 배지(확정/추정/미확정 비율)를 공통 컴포넌트로.

## F. 운영 관리 방법 (8)

### F1 [대표] 입력 담당과 승인자를 분리한다

지금 대표 1인이 둘 다 하면 통제가 형식이 된다. 최소 2인 — 입력(담당자) / 승인(대표).

### F2 [대표] 주 1회 30분 「현금 회의」를 고정한다

안건 3개로 고정 — ①판정 대기 정리 ②승인 대기 결정 ③다음 주 부족액.
이 시스템은 회의체가 없으면 데이터가 썩는다.

### F3 [대표] 증빙은 「받는 시점」에 올린다

사후에 모으면 반드시 누락된다. 슬랙에 사진만 올려도 검수함에 들어오게 되어 있다.

### F4 [대표] 월 마감을 다음 달 5일까지로 못 박는다

마감이 밀리면 V1(잔액 체인) 검증이 무의미해진다.

### F5 [세무] 세무대리인과 계정과목을 한 번 맞춘다

31개 계정이 세무대리인 장부와 1:1 대응하지 않으면 결산 때 두 번 일한다.

### F6 [대표] 급여 실액을 시스템에만 둔다

스프레드시트에 병행 보관하면 유출 경로가 둘이 된다. 역할 기반 마스킹이 무력화된다.

### F7 [대표] 판정 대기 8건에 기한을 정한다

「사유 미확정」은 시간이 지나면 아는 사람이 사라진다. 2주 안에 정리.
