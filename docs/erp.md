# 경영관리 시스템 — 33화면 (1~3차)

개발 사양서 v1.0 (2026-08-27)의 1~3차 범위 33화면 구현입니다. 오픈은 순차이고, 사양서와 어긋난 곳은
[erp-spec-gaps.md](./erp-spec-gaps.md)에 전부 적어 두었습니다.

## 접근

`/erp` — 회사 구글 워크스페이스 계정으로 로그인, `noindex`. 첫 진입 화면은 **현금흐름표**입니다.
배포와 환경변수는 [erp-deploy.md](./erp-deploy.md)를 보십시오.

관련 문서 — [배포 · 시트 전환](./erp-deploy.md) · [사양서와 어긋난 곳](./erp-spec-gaps.md) · [대표님이 하실 일](./erp-todo.md)

## 지켜지는 규칙

- **파생 뷰를 저장하지 않습니다.** 현금흐름표·현금현황 전용 테이블이 없고 매번 원장에서 계산합니다 (§4).
  그래서 두 화면의 숫자가 어긋날 수 없습니다 (G6).
- **물리 삭제가 없습니다.** DELETE를 실행하는 코드가 없고, 취소는 `-C` 상계 전표로만 합니다 (원칙 9).
- **모르면 null입니다.** 0으로 메우지 않고 `null_reason`과 무엇이 필요한지를 함께 돌려줍니다 (§10.2 · 원칙 8).
- **승인 없이는 지표가 아닙니다.** 승인 대기는 예약런웨이에만 반영됩니다 (§7.3).
- **개인별 급여는 응답 단계에서 마스킹합니다.** 프론트에서 숨기지 않습니다 (§13.3).

## 실행

```bash
pnpm install
pnpm dev          # http://localhost:3000/erp
pnpm test         # §18 T1~T15 + 2·3차 파생 뷰 (56개)
pnpm check        # 타입 검사
```

### 환경변수

| 이름               | 없을 때                                  | 용도                                                                         |
| ------------------ | ---------------------------------------- | ---------------------------------------------------------------------------- |
| `DATABASE_URL`     | §5.4 시드로 채운 메모리 저장소로 동작    | MySQL 접속                                                                   |
| `ERP_ROLE_MAP`     | —                                        | `{"이메일":"역할"}` JSON. 역할은 대표·부대표·재무·사업부리더·담당자·외부세무 |
| `ERP_DEFAULT_ROLE` | 개발 환경은 `재무`, 프로덕션은 접근 차단 | 배정 없는 사용자의 역할                                                      |

`DATABASE_URL`이 없으면 시드 27건이 메모리에 올라가고 8화면이 그대로 동작합니다 —
승인·수정·취소도 되지만 프로세스가 재시작되면 초기화됩니다. 실사용 전에 DB를 붙이십시오.

### DB 적재

```bash
pnpm db:push      # drizzle/schema.ts + drizzle/erpSchema.ts 마이그레이션
pnpm erp:seed     # §5.4 시드 적재 + V1~V8 이관 검증 리포트 (G2 · G3)
pnpm erp:check    # 적재하지 않고 검증만
```

계정과목 마스터가 비어 있으면 §8.1 초기 적재분을 코드에서 읽어 씁니다. 원장 시드 이관은
`shared/erp/seed.ts`의 `SEED_ENTRIES` · `SEED_DAY_SNAPSHOTS`를 그대로 INSERT하면 되고,
적재 후 종합 현황 화면의 이관 검증 리포트로 V1~V8을 확인합니다 (G2 · G3).

## 단계

화면은 33개가 전부 구현돼 있지만 **오픈은 순차**입니다 — 1차가 정확하지 않으면 2·3차 숫자도 전부 틀리기 때문입니다.
2·3차 화면은 값이 들어오기 전까지 「무엇이 있어야 이 지표가 나오는지」를 표로 보여줍니다. 빈 화면을 두지 않고,
추정치로 메우지도 않습니다 (원칙 8).

무엇이 막고 있는지는 [erp-todo.md](./erp-todo.md)에 담당별로 정리돼 있습니다.
