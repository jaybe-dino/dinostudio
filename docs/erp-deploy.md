# 배포 — Vercel + 로그인 (비밀번호 / 구글 워크스페이스 SSO)

> **먼저 알아야 할 것.** 이전까지 `/erp`는 로컬에서만 동작했습니다. Vercel 함수(`api/trpc`)가
> 문의 폼과 로그아웃만 서빙하고 있어서, 그대로 올렸다면 화면은 뜨고 데이터는 하나도 안 나왔을 겁니다.
> 지금은 Vercel 함수가 경영관리 시스템 전체를 서빙하고, 로그인은 회사 구글 계정으로 합니다.

---

## 0. 로그인 수단 — 둘 중 하나만 켜도 됩니다

|             | 비밀번호 로그인             | 구글 워크스페이스 SSO         |
| ----------- | --------------------------- | ----------------------------- |
| 준비 시간   | **1분** (환경변수 하나)     | 10분 (구글 콘솔 설정)         |
| 입력        | 회사 이메일 + 지정 비밀번호 | 구글 계정 선택                |
| 퇴사자 차단 | 비밀번호를 바꿔 전원 재배포 | 구글에서 계정만 정지하면 즉시 |
| 2단계 인증  | 없음                        | 구글 설정을 그대로 따름       |
| 권장        | **여는 첫 주까지**          | 정착 후                       |

둘 다 **같은 세션 쿠키**를 발급하므로 권한(§13.1)·감사로그(§11.1)는 완전히 같게 동작합니다.
둘 다 켜 두면 로그인 화면에 두 수단이 함께 나오고, 켜지지 않은 수단의 버튼은 아예 그리지 않습니다.

> **비밀번호 로그인이 SSO보다 약한 지점** — 공용 비밀번호는 사람이 나갈 때 되찾을 방법이
> 「비밀번호 교체 후 전원 재로그인」뿐이고, 2단계 인증이 없습니다. 서버리스라 시도 횟수 제한도
> 인스턴스별로만 걸려서 무차별 대입을 늦출 뿐 막지는 못합니다 — 실제 방어선은 **비밀번호 길이**입니다.
> 그래서 임시 수단으로 쓰고, 구글 SSO가 붙으면 `ERP_PASSWORD`를 지우십시오.

### ⓪ 비밀번호 로그인만 먼저 켜기 (1분)

Vercel 환경변수 3개면 끝입니다. ①은 건너뛰고 ②로 가십시오.

| 이름                 | 값                                                                      |
| -------------------- | ----------------------------------------------------------------------- |
| `SESSION_SECRET`     | 아무 긴 임의 문자열 (아래 ② 참고)                                       |
| `ERP_PASSWORD`       | 정하실 비밀번호 — **10자 이상**, 미만이면 로그인이 아예 켜지지 않습니다 |
| `ERP_ALLOWED_DOMAIN` | `dinostudio.kr`                                                         |
| `ERP_ROLE_MAP`       | `{"jaybe@dinostudio.kr":"대표"}`                                        |

이메일을 함께 받는 이유는 **누가 승인했는지가 감사로그에 남아야 하기 때문**입니다 (§11.1).
비밀번호는 문을 여는 열쇠일 뿐이고, 신원은 이메일입니다. 허용 도메인 밖 이메일은 비밀번호가 맞아도 막힙니다.

사람마다 다른 비밀번호를 주고 싶으시면 `ERP_PASSWORDS`에
`{"cfo@dinostudio.kr":"...","tax@partner.co.kr":"..."}` 형태로 넣으십시오 — 여기 적힌 계정은
공용 비밀번호로는 들어올 수 없고, 안 적힌 계정만 `ERP_PASSWORD`를 씁니다. 한 사람만 차단할 때 유용합니다.

**끄는 법** — `ERP_PASSWORD`(와 `ERP_PASSWORDS`)를 지우고 재배포하면 그 즉시 비밀번호 경로가 사라집니다.

## 1. 대표님이 하실 일 — 순서대로 4단계 (약 30분)

### ① 구글 OAuth 클라이언트 발급 (10분) — 나중에 하셔도 됩니다

[Google Cloud Console](https://console.cloud.google.com/apis/credentials) →
**사용자 인증 정보 만들기 → OAuth 클라이언트 ID**

| 항목                     | 값                                            |
| ------------------------ | --------------------------------------------- |
| 애플리케이션 유형        | 웹 애플리케이션                               |
| 승인된 자바스크립트 원본 | `https://<배포주소>`                          |
| 승인된 리디렉션 URI      | `https://<배포주소>/api/auth/google/callback` |

로컬에서도 쓰시려면 리디렉션 URI에 `http://localhost:3000/api/auth/google/callback`을 하나 더 넣으십시오.
Vercel 미리보기 배포에서 로그인하시려면 그 주소(`https://<프리뷰>.vercel.app/api/auth/google/callback`)도
등록해야 합니다 — 미리보기 주소는 배포마다 바뀌므로, 운영 도메인에서만 시험하시는 편이 간단합니다.
발급되면 **클라이언트 ID**와 **클라이언트 보안 비밀번호**가 나옵니다 — 이 두 값은 채팅이나 문서에 붙이지 마시고
Vercel 환경변수에만 넣으십시오.

동의 화면은 **내부(Internal)** 로 설정하시면 워크스페이스 구성원만 로그인할 수 있어 한 겹 더 막힙니다.

### ② Vercel 환경변수 등록

Vercel 프로젝트 → Settings → Environment Variables (Production · Preview 둘 다)

| 이름                   | 값                                                  | 없으면                                                    |
| ---------------------- | --------------------------------------------------- | --------------------------------------------------------- |
| `SESSION_SECRET`       | 아무 긴 임의 문자열 (32자 이상)                     | 세션을 서명할 수 없어 로그인 실패 (**두 수단 공통 필수**) |
| `ERP_PASSWORD`         | 정하실 비밀번호 (10자 이상)                         | 비밀번호 로그인 버튼이 안 나옵니다                        |
| `GOOGLE_CLIENT_ID`     | ①에서 발급 (선택)                                   | 구글 로그인 버튼이 안 나옵니다                            |
| `GOOGLE_CLIENT_SECRET` | ①에서 발급 (선택)                                   | 〃                                                        |
| `ERP_ALLOWED_DOMAIN`   | `dinostudio.kr`                                     | **아무도 못 들어옵니다** (기본값이 「닫힘」입니다)        |
| `ERP_ROLE_MAP`         | `{"대표이메일":"대표","재무이메일":"재무"}`         | 로그인은 되지만 「역할 미지정」으로 막힙니다              |
| `DATABASE_URL`         | 2번 참조                                            | 시드 데이터가 메모리에 올라가고 재시작 시 초기화됩니다    |
| `ERP_ALLOWED_EMAILS`   | (선택) 외부 세무대리인 등 도메인 밖 계정, 쉼표 구분 | —                                                         |
| `ERP_PASSWORDS`        | (선택) 사람별 비밀번호 JSON                         | 전원이 `ERP_PASSWORD` 하나를 공유합니다                   |

`SESSION_SECRET` 외에는 **최소 3개**(`ERP_PASSWORD` · `ERP_ALLOWED_DOMAIN` · `ERP_ROLE_MAP`)면
로그인이 됩니다. 구글 SSO는 나중에 붙여도 이미 만든 세션이나 데이터에 영향이 없습니다.

**`SESSION_SECRET`이 뭔가요** — 로그인 세션 쿠키가 위조되지 않았는지 확인하는 데 쓰는
**아무 긴 임의 문자열**입니다. 뜻이 있는 값이 아니고, 한 번 정해서 넣어두면 그만입니다.
(이 값이 바뀌면 모두 로그아웃됩니다. 새는 순간 남이 로그인한 척할 수 있으니 채팅·문서에 붙이지 마십시오.)

만드는 법 — 브라우저에서 F12 → 콘솔에 붙여넣고 Enter, 나온 문자열을 복사하십시오.

```js
crypto.randomUUID() + crypto.randomUUID() + crypto.randomUUID();
```

맥 터미널을 쓰신다면 `openssl rand -base64 48` 도 같은 일을 합니다.

역할은 여섯 가지입니다 — `대표` · `부대표` · `재무` · `사업부리더` · `담당자` · `외부세무`.
승인 한도와 급여·부채 노출이 여기서 갈립니다 (§13.1).

### ③ DB 연결 (2번 표에서 하나 고르신 뒤)

```
pnpm db:push      # 테이블 생성
pnpm erp:seed     # §5.4 시드 27건 + 일계 7행 적재 + V1~V8 검증 리포트 출력
```

리포트에서 V1(잔액 체인) · V7(중복) · V8(방향)이 불일치로 나오는 게 **정상**입니다 —
고쳐서 통과시키는 항목이 아니라 그대로 노출하는 항목입니다.

### ④ 도메인 연결 — `admin.dinostudio.kr`

Vercel 프로젝트 → Settings → Domains → `admin.dinostudio.kr` 추가 →
안내되는 CNAME 레코드를 도메인 DNS에 등록합니다.

이 호스트에서는 **루트(`/`)가 곧 경영관리 시스템**입니다. 마케팅 사이트는 보이지 않습니다.
색인 차단·프레임 차단·캐시 금지 헤더가 이 호스트 전체에 붙습니다.
`dinostudio.kr/erp` 도 계속 열리지만, 실사용은 `admin.dinostudio.kr` 로 하십시오 —
세션 쿠키가 호스트 전용이라 두 도메인이 서로 섞이지 않습니다.

### ⑤ 확인

`https://admin.dinostudio.kr` → 회사 이메일 + 비밀번호(또는 구글 로그인) →
현금 현황에서 P0 부족액이 **−272,110** 으로 나오면 성공입니다.

## 2. DB — Neon (PostgreSQL) 으로 결정 (2026-09-02)

사양서 §15 의 권고안입니다. 개발 기간에는 레포 통일성 때문에 MySQL 로 진행했고,
DB 를 붙이는 시점에 PostgreSQL 로 옮겼습니다. 회계 로직은 한 줄도 바뀌지 않았습니다
(`shared/erp` 는 DB 를 모릅니다).

### 붙이는 방법 — Vercel 안에서 끝납니다 (2클릭)

1. **Vercel → dinostudio 프로젝트 → Storage** 탭
2. **Create Database → Neon** 선택 → 리전은 아무 곳(가까운 곳: Singapore 또는 Tokyo)
3. Connect Project 하면 **`DATABASE_URL` 이 Production 에 자동으로 꽂힙니다**

> 연결 문자열을 복사할 필요도, 비밀번호를 어디에 붙일 필요도 없습니다. 그래서
> 이 경로를 골랐습니다 — 비밀값이 사람 손을 거치지 않는 것이 가장 안전합니다.

Vercel Marketplace 를 쓰지 않고 `neon.tech` 에서 직접 만드셨다면 연결 문자열이
이런 모양입니다. 이때는 Vercel 환경변수에 `DATABASE_URL` 로 직접 넣으십시오.

```
postgresql://<user>:<password>@ep-xxxx-pooler.<region>.aws.neon.tech/<db>?sslmode=require
```

### 넣은 다음

```
npm run db:push      # 마이그레이션 적용 (테이블 23개 · enum 14종)
DATABASE_URL=... npx tsx server/erp/seedDb.ts   # 시드 적재 + V1~V8 검증 리포트
```

제가 대신 돌려 드릴 수 있습니다 — 넣으셨다고만 알려주십시오.

### 왜 무료로 충분한가

Neon 무료 티어는 0.5GB 저장 · 월 190시간 컴퓨트입니다. 우리 원장은 월 수백 건이라
1년치가 수십 MB 수준이고, 서버리스라 안 쓰는 시간에는 컴퓨트를 안 씁니다.

### 국내 보관이 요건이라면

회계 데이터의 국내 리전 보관이 요건이면 Neon(싱가포르/도쿄)이 아니라
**AWS RDS PostgreSQL (ap-northeast-2 서울, 월 $15~)** 로 가야 합니다. 스키마는
그대로 쓰고 연결 문자열만 바뀝니다 — 다만 서버리스 연결 수 때문에 RDS Proxy 나
`drizzle-orm/postgres-js` 풀 설정이 필요합니다. 요건인지만 알려주십시오.

## 3. 지금 구글 시트를 계속 쓰다가 넘어오는 방법

시트를 당장 버릴 필요 없습니다. **넘어오는 날짜를 하루 정하고**, 그날 이관 화면에서 한 번만 옮기면 됩니다.

### 전환 전 (지금~전환일) — 시트를 계속 쓰시되 두 가지만

1. **공유 범위를 「제한됨」으로** (오늘 · 5분) — 지금은 링크 가진 누구나 편집할 수 있는 상태입니다.
   전환일과 무관하게 지금 해야 합니다.
2. **금액을 적요 칸에 쓰지 마십시오** — 금액 칸에 숫자만, 단위는 원으로.
   지금 판정 대기 8건 중 5건이 이것 때문에 생겼습니다. 이관기는 적요 칸 숫자를 금액으로 올리지 않습니다.

### 전환일 (하루, 30분)

`/erp` → **기준 · 통제 → 시트 이관**

1. 시트에서 **전환 시작일 이후 구간**을 헤더 줄까지 함께 복사
2. 이관 화면에 붙여 넣고 **미리보기** — 무엇이 판정 대기로 떨어지는지 먼저 보여줍니다
3. 판정 대기가 많으면 시트에서 고치고 다시 붙여 넣으십시오 (아직 저장 전입니다)
4. **확인 · 원장에 적재**
5. 종합 현황에서 V1~V8 리포트 확인 → 대표·재무 서면 확인

이관기가 지키는 것 (§5.2)

| 시트                         | 원장                   | 실패하면                                                      |
| ---------------------------- | ---------------------- | ------------------------------------------------------------- |
| 일자                         | `cash_date`            | 못 읽으면 버리지 않고 「읽지 못한 줄」에 사유와 함께 남깁니다 |
| 항목                         | `title`                | 공란이면 **판정 대기**                                        |
| 적요                         | `note_raw` (원문 보존) | —                                                             |
| 지출 / 수입 금액             | `amount`, `direction`  | 파싱 실패 → `amount = null` · 판정 대기                       |
| 적요 칸에 들어간 금액        | **승격하지 않음**      | 후보 금액으로만 남기고 현금 현황 토글에서만 참조              |
| 단위 불명 (80 · 1,200 · 350) | `null`                 | 만원인지 원인지 추정하지 않습니다                             |
| 계정 · 귀속                  | 비워 둠                | 이관 후 사람이 태깅                                           |

같은 줄을 두 번 붙여 넣어도 중복 적재되지 않습니다 (`UNIQUE(source, source_ref)`).

### 전환 후 (§5.6 동결 절차)

1. 시트 사본을 `[동결] 데일리 현금흐름 ~YYYY-MM-DD` 로 만들고 **보기 전용**으로 전환
2. 원본 시트 상단에 「이 날짜부터 이 시트는 사용하지 않습니다」 고정 행 추가
3. 이후 시트 수정은 시스템에 반영되지 않습니다 — **재이관 기능은 제공하지 않습니다**

원본이 둘이 되는 순간 반드시 어긋납니다. 그게 지금 시트에서 벌어지고 있는 일입니다.

### 병행 기간에 지켜야 할 한 가지

전환 전에는 **시트가 원본**, 전환 후에는 **시스템이 원본**입니다. 겹치는 기간을 두지 마십시오.
꼭 겹쳐야 한다면 시트를 읽기 전용 참고로만 두고, 입력은 시스템에서만 하십시오.

## 4. 로그인 동작

| 상황                   | 화면                                                                                                                             |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 로그인 안 함           | 이메일·비밀번호 입력칸 (+ 구글 SSO를 켰다면 그 버튼도 함께)                                                                      |
