# 대표님이 하실 일 — 최종 체크리스트

> **오픈 당일에는 `erp-open.md` 를 보십시오.** 이 문서는 배경과 상세이고,
> 그쪽이 순서대로 따라가는 문서입니다.

운영에 필요한 설정과 자료 확인 목록입니다. 완료 여부는 실제 운영 화면과 저장 결과로 확인하십시오.
금액 입력, 증빙 검수, 최종 승인은 서로 다른 단계입니다.

아래 예시는 입력 형식을 설명합니다. 예시 금액을 실제 회사 값으로 저장하지 말고, 기준일과 근거를 확인한 값을 사용하십시오.

## 2단계 — 이번 주

`admin.dinostudio.kr` → **기준값** 화면에서 넣습니다. 입력칸에 모양이 회색으로
떠 있으니 그대로 채우시면 됩니다.

### ① 급여 실액 · 5분 ⭐ 가장 급함 (아직)

| 기준값                   | 넣을 것                      |
| ------------------------ | ---------------------------- |
| `payroll_monthly_actual` | 확인된 최신 월 급여 총액 (정수 원) |

> 이것 하나가 없어서 **런웨이 3종이 전부 「계산 불가」**입니다. 번레이트의 최대
> 항목입니다. 개인별 금액은 어느 화면에도 안 나오고 총액만 씁니다.

### ② 현금과 지평 · 10분

| 기준값                     | 지금 값                 | 뜻                           |
| -------------------------- | ----------------------- | ---------------------------- |
| `cash_on_hand`             | `110000000` (시트 잠정) | 지금 통장 잔액 합계          |
| `cash_requirement_horizon` | `2026-09-30` ✅         | 「부족액」이 며칠치를 보는지 |

> `cash_on_hand` 는 9/13 시트 머리말의 「잔고」를 옮겨 둔 **잠정값**입니다.
> 실제 통장 잔액 합계를 확인해 덮어써 주십시오.

### ③ 계좌와 여신 · 15분

| 기준값          | 그대로 붙여넣고 숫자만 바꾸십시오                                                                |
| --------------- | ------------------------------------------------------------------------------------------------ |
| `bank_accounts` | `[{"code":"1110-01","name":"주거래","bank":"기업은행","balance":30000000}]`                      |
| `credit_lines`  | `[{"id":"1","name":"기업은행 마이너스","kind":"마이너스통장","limit":50000000,"used":20000000}]` |

- 계좌가 여러 개면 `},{` 로 이어 붙이십시오
- `kind` 는 `마이너스통장` · `법인카드` · `기타` 중 하나
- **한도는 현금과 합쳐 보여 주지 않습니다** — 빌리는 돈이고 은행이 줄일 수 있습니다

### ④ 판정 대기 47건 ⭐ 가장 큰 덩어리

**승인 대기함** 또는 **집행원장** → 상태 「판정 대기」로 필터.

| 무엇                              | 어떻게                                                    |
| --------------------------------- | --------------------------------------------------------- |
| 적요 칸에 금액이 있는 줄 (대부분) | 상세의 금액 보완에서 근거와 함께 저장 — 승인 대기로 이동하며 증빙·계정 검토와 승인은 별도입니다 |
| 부가세2차 「1,200」               | 원·천원·만원 중 무엇인지. 몰라서 후보로도 안 올렸습니다   |
| 박재우 2차 · 웨어하우스(해외)     | 9/13 시트에서 금액 칸을 비우셔서 내려온 건입니다          |

> 이것 때문에 **현금흐름표의 「종료」가 모든 날에서 계산 불가**입니다. 다만
> 그 옆 **「시트 잔액」**에 시트에 적힌 그 날 잔액이 나오므로, 금액을 채우기
> 전에도 잔액은 보실 수 있습니다. 둘이 서면 **차이가 곧 원장에 아직 안 들어온
> 돈**입니다.

### ⑤ 차입 약정서 5건 · 20분

**부채 원장** 화면에서 건별로 넣습니다 (조대표 1.5억 · 의장 0.9억 포함).

필요한 것 — 실행된 회사 차입의 현재 원금 잔액 · 만기일 · 연 이자율 · 상환조건 · 월 이자액 · 약정서 링크

부채 원장의 「차입 등록 · 조건 수정」에서 저장합니다. 13주 계획에 반영할 지급일과 원금·이자는 「상환 일정 등록 · 수정」에 별도로 저장합니다. 만기 일시 지급 이자를 월 이자액으로 입력하지 마십시오. 다른 법인 명의나 미서명 초안은 실행 여부와 귀속을 확인한 뒤 등록하십시오.

> 만기 알람 D-30/14/7/0 이 이미 등록돼 있는데 **만기가 없어 하나도 울리지 않습니다.**

## 3단계 — 슬랙 ✅ 끝났습니다

봇이 아래 다섯 채널에 모두 들어가 있는 것을 확인했습니다.

| 채널               | 채널 ID     |
| ------------------ | ----------- |
| `#재무-집행요청`   | CM1RX8X96   |
| `#재무-승인요청`   | CM4154DTQ   |
| `#결제요청방-일반` | C0348RTFTV0 |
| `#결제요청방-실비` | C034MED1K33 |
| `#계산서발행요청`  | CMHQPQJBF   |

`SLACK_EXPENSE_CHANNELS=*` 이므로 **봇을 초대한 채널이 곧 수집 대상**입니다.
채널을 늘리시려면 그 채널에서 `/invite @봇` 만 하시면 됩니다 — 저를 부르실
필요도, 환경변수를 고치실 필요도 없습니다.

### 과거 메시지는 자동으로 안 들어옵니다 — 한 번 눌러 주십시오 · 5분

슬랙 연동은 **켠 다음**에 올라온 메시지만 받습니다. 한 달 전 집행요청은
따로 가져와야 합니다.

> `admin.dinostudio.kr` → **수집 검수함** → 「슬랙 과거 메시지 가져오기」
> → 기간을 **365일**로 두고 **가져오기**

⚠️ **30일로 하면 0건이 나옵니다.** 채널 이력을 직접 확인해 보니 지출 채널에
최근 글이 없습니다.

| 채널               | 마지막 실제 메시지             |
| ------------------ | ------------------------------ |
| `#재무-집행요청`   | 1년 넘게 없음 (봇 참여 알림만) |
| `#결제요청방-일반` | 2025-10-30                     |
| `#결제요청방-실비` | 2025-03-25                     |

기능이 고장난 것이 아니라 **그 기간에 글이 없는 것**입니다. 실제 데이터를
가져오시려면 365일을 고르셔야 합니다.

- 끝까지 못 가면 버튼이 **「이어서 가져오기」**로 바뀝니다. 그대로 다시
  누르시면 멈춘 자리에서 계속합니다 (슬랙이 속도를 조이기 때문에 몇 번
  나눠 눌러야 할 수 있습니다)
- **여러 번 눌러도 같은 건이 두 번 들어가지 않습니다**
- 가져온 것은 **검수함까지만** 옵니다. 원장 적재는 건별로 확인하고 누르셔야
  합니다
- 실비 정산 요청에는 **주민등록번호**가 들어 있습니다. 원천징수 신고에 필요한
  값이라 그대로 보관하되, 화면에는 `******-*******` 로만 보입니다.
  「주민번호 보기」를 누르고 **비밀번호를 다시 입력**하면 원본이 열리고,
  누가 언제 열었는지 기록이 남습니다. 대표·재무만 열 수 있습니다

**권한(`channels:read` · `files:read`)과 앱 이름(「디노 경영관리」)은 이미
끝났습니다.** 남은 것은 위의 「가져오기」를 누르는 것뿐입니다.

### ⚠️ 시트를 다시 깔면 검수함도 비워집니다

「시트를 최종본으로 다시 깔기」는 원장·전표·일계뿐 아니라 **검수함까지**
비웁니다. 그래서 다시 깐 뒤에는 **슬랙 수집을 한 번 더 돌려야** 합니다.
화면이 지운 건수를 네 가지로 다 적어 주고, 검수함이 비워졌으면
「슬랙 수집을 다시 돌리십시오」라고 알려 줍니다.

## 4단계 — 세무대리인 통화 1회 (40분)

한 번에 물어보시라고 모았습니다. 답이 오면 제가 바로 반영합니다.

| #   | 물어볼 것                                                                        | 왜 필요한가                                                             |
| --- | -------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| 1   | **기초 재무상태표** 자본·이월                                                    | 재무제표 5종이 전부 「가결산」이고 시산표 차액이 노출                   |
| 2   | **이관 조정 사유** — 08/24 시작 잔액 불일치 (시트 18,000,000 vs 이관 51,114,118) | **8월 마감의 유일한 이관 측 장애**                                      |
| 3   | **부가세 2차 금액** — 12,000,000(카드) vs 원장 적요 1,200                        | **P0 부족액의 부호가 뒤집힙니다**                                       |
| 4   | 적격증빙 **3만 원** · 사업소득 **3.3%** · 기타소득 **8.8%** 가 맞는지            | 지금 코드 상수. 확인되면 설정값으로 뺍니다                              |
| 5   | **접대비 계정 신설** 여부                                                        | 지금 계정과목 마스터에 접대비가 **없습니다**                            |
| 6   | **통과원가** 총액인가 순액인가                                                   | 중개면 예수금(부채), 원가 구조면 영업활동 — 현금흐름표 3구간이 갈립니다 |
| 7   | **지출증명서류 합계표** 대상인지                                                 | 증빙불비가산세 계산                                                     |
| 8   | **VAT 표기** — IP(vat별도) vs 네트워크(VAT 포함) 통일 여부                       | 슬랙 파서와 부가세 화면                                                 |
| 9   | **대리납부(역과세)** 2건 — 해외 SaaS · 광고                                      | —                                                                       |
| 10  | **계정과목 대조** — 세무대리인 장부와 우리 계정                                  | 세무 제출 패키지가 이 단위로 나갑니다                                   |

답을 받으시면 **외부세무** 역할로 계정을 하나 만들어 드리면 세무대리인이 직접
들어와서 세무 제출 패키지를 받아갈 수 있습니다.

## 5단계 — 대표님만 정할 숫자

정하시는 대로 기준값 화면에 넣으면 그 화면이 살아납니다.

| 기준값                        | 넣는 모양                            | 살아나는 화면        |
| ----------------------------- | ------------------------------------ | -------------------- |
| `ar_aging_buckets`            | `[30, 60, 90]` 또는 `[15, 30, 60]`   | 채권 연령분석        |
| `allocation_basis`            | `"매출 비율"`                        | 사업부·프로젝트 손익 |
| `pipeline_probability`        | `{"상":0.7,"중":0.4,"하":0.1}`       | 13주 자금계획        |
| `headcount`                   | `8`                                  | 인당 매출·인당 이익  |
| `project_remaining_estimates` | `{"PRJ-0132": 12000000}`             | 프로젝트 예상 마진   |
| `subscriptions`               | `[{"name":"Adobe","monthly":60000}]` | 번레이트 조건 6      |
| `opening_equity`              | `0`                                  | 재무제표 5종         |
| `debt_long_term_total`        | `240000000`                          | 부채 원장            |
| `approval_single_limit`       | `20000000` (지금 값)                 | 승인 한도            |

**프로젝트 마스터**에서 넣을 것 — `계약 금액`(매출)과 `원가 예산`(지출)은
**다른 칸**입니다. 하나로 두면 프로젝트 마진과 예산 대비 실적 중 한쪽이
반드시 틀립니다.

결정만 하면 되는 것 — 자산화 기준금액 · 대손 설정률 · 회수 확률 ·
매출·이익 목표 · 사업부 구분 기준 · 손익 귀속 기준일 ·
**틱톡샵 정산 4가지**(통화 · 매출 인식 시점 · 수수료 계정 · 총액/순액 —
**첫 정산 처리가 기준으로 굳습니다**).

| 대표님이 주시는 것    | 제가 하는 것                                             |
| --------------------- | -------------------------------------------------------- |
| `DATABASE_URL` 넣었다 | 재배포가 테이블 생성 → 화면에서 시드 버튼 → V1~V8 리포트 |

| 「이메일로 간다」     | 이메일 발송 어댑터 (30분)                                |
| 실제 숫자 다 넣으셨다 | 여신·계좌·예산 화면을 실제 데이터로 다시 검증            |
