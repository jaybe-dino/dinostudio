# 대표님이 하실 일 — 최종 체크리스트

개발은 끝났습니다. QA 62항목 중 **개발만으로 되는 항목은 남지 않았습니다.**
아래는 전부 「값을 넣거나 결정해야」 그 화면이 살아나는 것들입니다.

**붙여넣을 값을 그대로 적었습니다.** 숫자만 우리 것으로 바꾸시면 됩니다.

---

## 1단계 — 오늘 (합계 35분)

### ① 구글 시트 잠그기 · 5분

1. 데일리 현금흐름 · 운영 전체 시트 열기
2. 우상단 **공유** → 「링크가 있는 모든 사용자」를 **제한됨**으로
3. **파일 → 버전 기록 → 버전 기록 보기** → 모르는 사람의 편집이 있는지 확인
   - 있으면 그 시점 **이전**을 이관 기준으로 잡아야 하므로 저에게 알려주십시오

> 이관보다 먼저입니다. 지금은 링크를 가진 누구나 편집할 수 있습니다.

### ② DB 연결 · 15분

**Vercel → dinostudio 프로젝트 → Settings → Environment Variables → Production**

| Key            | Value                                                                        |
| -------------- | ---------------------------------------------------------------------------- |
| `DATABASE_URL` | `mysql://아이디:비밀번호@호스트:3306/DB이름?ssl={"rejectUnauthorized":true}` |
| `CRON_SECRET`  | 터미널에서 `openssl rand -base64 32` 를 돌린 **결과값**                      |

> ⚠️ **두 값 모두 저에게 붙여넣지 마십시오.** Vercel 에 직접 넣으시고 「넣었다」만
> 알려주시면 됩니다. 채팅에 올라온 비밀값은 그 순간 폐기 대상이 됩니다.

넣으셨다고 알려주시면 제가 `npm run db:push` 로 마이그레이션 `0006`·`0007` 을
적용하고, 시드 27건 + 일계 7행을 적재한 뒤 **V1~V8 이관 검증 리포트**를 돌려
어디가 안 맞는지 표로 드립니다.

`CRON_SECRET` 이 없으면 알림 크론이 아무 것도 하지 않습니다 (그렇게 만들어
두었습니다 — 인증 없이 열어 두면 밖에서 알림을 무한히 트리거할 수 있습니다).

### ③ 역할 배정 · 10분

같은 화면에서 `ERP_ROLE_MAP` 을 이렇게 바꿉니다. **한 줄로** 넣으십시오.

```json
{
  "jaybe@dinostudio.kr": "대표",
  "재무이메일@dinostudio.kr": "재무",
  "리더이메일@dinostudio.kr": "사업부리더",
  "담당자이메일@dinostudio.kr": "담당자"
}
```

쓸 수 있는 역할은 여섯 가지입니다 — `대표` `부대표` `재무` `사업부리더` `담당자`
`외부세무` `외부열람`.

- **외부세무** — 세무대리인. 원장을 보고 세무 제출 패키지를 받습니다
- **외부열람** — 화면은 보지만 **파일로 내보낼 수 없습니다**

여기에 없는 이메일은 로그인해도 「역할 미지정」으로 막힙니다.

## 2단계 — 이번 주 (합계 1시간 20분)

`admin.dinostudio.kr` → **기준값** 화면에서 넣습니다. 입력칸에 모양이 회색으로
떠 있으니 그대로 채우시면 됩니다.

### ① 급여 실액 · 5분 ⭐ 가장 급함

| 기준값                   | 넣을 것                      |
| ------------------------ | ---------------------------- |
| `payroll_monthly_actual` | `52000000` (월 총액, 숫자만) |

> 이것 하나가 없어서 **런웨이 3종이 전부 「계산 불가」**입니다. 번레이트의 최대
> 항목입니다. 개인별 금액은 어느 화면에도 안 나오고 총액만 씁니다.

### ② 현금과 지평 · 10분

| 기준값                     | 넣을 것      | 뜻                           |
| -------------------------- | ------------ | ---------------------------- |
| `cash_on_hand`             | `18000000`   | 지금 통장 잔액 합계          |
| `cash_requirement_horizon` | `2026-09-30` | 「부족액」이 며칠치를 보는지 |

### ③ 계좌와 여신 · 15분

| 기준값          | 그대로 붙여넣고 숫자만 바꾸십시오                                                                |
| --------------- | ------------------------------------------------------------------------------------------------ |
| `bank_accounts` | `[{"code":"1110-01","name":"주거래","bank":"기업은행","balance":30000000}]`                      |
| `credit_lines`  | `[{"id":"1","name":"기업은행 마이너스","kind":"마이너스통장","limit":50000000,"used":20000000}]` |

- 계좌가 여러 개면 `},{` 로 이어 붙이십시오
- `kind` 는 `마이너스통장` · `법인카드` · `기타` 중 하나
- **한도는 현금과 합쳐 보여 주지 않습니다** — 빌리는 돈이고 은행이 줄일 수 있습니다

### ④ 판정 대기 8건 · 30분

**집행원장** 화면 → 상태 「판정 대기」로 필터.

| 무엇                   | 어떻게                                        |
| ---------------------- | --------------------------------------------- |
| 적요칸 금액 5건        | 실제 금액을 확인해 입력 (80 · 350 · 1,200 등) |
| 항목명 없는 30,000,000 | 무엇에 쓴 돈인지                              |
| 중복 의심 7,500,000    | 중복이면 취소, 아니면 사유를 적고 진행        |

> 08/26부터 **현금흐름표 종료 잔액이 계산되지 않고**, 8월 마감이 막혀 있습니다.

### ⑤ 차입 약정서 5건 · 20분

**부채 원장** 화면에서 건별로 넣습니다 (조대표 1.5억 · 의장 0.9억 포함).

필요한 것 — 만기일 · 이자율 · 상환조건 · 월 이자액

> 만기 알람 D-30/14/7/0 이 이미 등록돼 있는데 **만기가 없어 하나도 울리지 않습니다.**

## 3단계 — 슬랙 (재무 30분)

| 순서 | 할 일                                                                           |
| ---- | ------------------------------------------------------------------------------- |
| 1    | api.slack.com/apps → **Create New App** → From scratch → 워크스페이스 선택      |
| 2    | **Event Subscriptions** → ON → Request URL 에 아래 주소                         |
|      | `https://admin.dinostudio.kr/api/integrations/slack/events`                     |
| 3    | **Subscribe to bot events** → `message.channels` 추가 → Save                    |
| 4    | **OAuth & Permissions** → Scopes 에 `chat:write` · `channels:history` → Install |
| 5    | 지출 채널 두 곳에 `/invite @봇이름`                                             |
| 6    | Vercel 에 아래 4개 등록                                                         |

| Key                      | Value                                      |
| ------------------------ | ------------------------------------------ |
| `SLACK_SIGNING_SECRET`   | 슬랙 앱 Basic Information → Signing Secret |
| `SLACK_BOT_TOKEN`        | OAuth & Permissions → `xoxb-` 로 시작      |
| `SLACK_EXPENSE_CHANNELS` | 채널 ID 두 개, 쉼표 구분 (`C01ABC,C02DEF`) |
| `SLACK_NOTIFY_CHANNEL`   | 알림 받을 채널 ID                          |

> **슬랙 워크스페이스가 휴면이면 먼저 살려야 합니다.** 못 살리면 알려주십시오 —
> 이메일 발송으로 30분이면 바꿉니다 (다만 이메일로는 알림만 되고 지출 수집은
> 안 됩니다).
>
> 채널 ID 는 채널 우클릭 → 「채널 세부정보 보기」 맨 아래에 있습니다.

## 4단계 — 세무대리인 통화 1회 (40분)

한 번에 물어보시라고 모았습니다. 답이 오면 제가 바로 반영합니다.

| #   | 물어볼 것                                                                        | 왜 필요한가                                                             |
| --- | -------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| 1   | **기초 재무상태표** 자본·이월                                                    | 재무제표 5종이 전부 「가결산」이고 시산표 차액이 노출                   |
| 2   | **이관 조정 사유** — 08/24 시작 잔액 불일치 (시트 18,000,000 vs 이관 51,114,118) | **8월 마감의 유일한 이관 측 장애**                                      |
| 3   | **부가세 2차 금액** — 12,000,000(카드) vs 원장 적요 1,200                        | **P0 부족액의 부호가 뒤집힙니다**                                       |
| 4   | 적격증빙 **3만 원** · 사업소득 **3.3%** · 기타소득 **8.8%** 가 맞는지            | 지금 코드 상수. 확인되면 설정값으로 뺍니다                              |
| 5   | **접대비 계정 신설** 여부                                                        | 지금 계정과목 마스터에 접대비가 **없습니다**                            |
| 6   | **통과원가** 총액인가 순액인가                                                   | 중개면 예수금(부채), 원가 구조면 영업활동 — 현금흐름표 3구간이 갈립니다 |
| 7   | **지출증명서류 합계표** 대상인지                                                 | 증빙불비가산세 계산                                                     |
| 8   | **VAT 표기** — IP(vat별도) vs 네트워크(VAT 포함) 통일 여부                       | 슬랙 파서와 부가세 화면                                                 |
| 9   | **대리납부(역과세)** 2건 — 해외 SaaS · 광고                                      | —                                                                       |
| 10  | **계정과목 대조** — 세무대리인 장부와 우리 계정                                  | 세무 제출 패키지가 이 단위로 나갑니다                                   |

답을 받으시면 **외부세무** 역할로 계정을 하나 만들어 드리면 세무대리인이 직접
들어와서 세무 제출 패키지를 받아갈 수 있습니다.

## 5단계 — 대표님만 정할 숫자

정하시는 대로 기준값 화면에 넣으면 그 화면이 살아납니다.

| 기준값                        | 넣는 모양                            | 살아나는 화면        |
| ----------------------------- | ------------------------------------ | -------------------- |
| `ar_aging_buckets`            | `[30, 60, 90]` 또는 `[15, 30, 60]`   | 채권 연령분석        |
| `allocation_basis`            | `"매출 비율"`                        | 사업부·프로젝트 손익 |
| `pipeline_probability`        | `{"상":0.7,"중":0.4,"하":0.1}`       | 13주 자금계획        |
| `headcount`                   | `8`                                  | 인당 매출·인당 이익  |
| `project_remaining_estimates` | `{"PRJ-0132": 12000000}`             | 프로젝트 예상 마진   |
| `subscriptions`               | `[{"name":"Adobe","monthly":60000}]` | 번레이트 조건 6      |
| `opening_equity`              | `0`                                  | 재무제표 5종         |
| `debt_long_term_total`        | `240000000`                          | 부채 원장            |
| `approval_single_limit`       | `20000000` (지금 값)                 | 승인 한도            |

**프로젝트 마스터**에서 넣을 것 — `계약 금액`(매출)과 `원가 예산`(지출)은
**다른 칸**입니다. 하나로 두면 프로젝트 마진과 예산 대비 실적 중 한쪽이
반드시 틀립니다.

결정만 하면 되는 것 — 자산화 기준금액 · 대손 설정률 · 회수 확률 ·
매출·이익 목표 · 사업부 구분 기준 · 손익 귀속 기준일 ·
**틱톡샵 정산 4가지**(통화 · 매출 인식 시점 · 수수료 계정 · 총액/순액 —
**첫 정산 처리가 기준으로 굳습니다**).

## 6단계 — 확인만 하시면 되는 것

| 무엇                     | 어떻게 확인                                                                 |
| ------------------------ | --------------------------------------------------------------------------- |
| 로그인 전 정보 노출      | 시크릿 창으로 `admin.dinostudio.kr` → **화면 이름이 하나도 안 보여야** 정상 |
| 본사 사이트              | `dinostudio.kr` 이 CSP 적용 후에도 정상인지                                 |
| 기업은행 거래내역 컬럼명 | 인터넷뱅킹에서 엑셀 받아 **첫 줄(머리글)만** 알려주십시오                   |
| 백업 복구 리허설         | DB 붙인 직후 1회 — 「복구된다」는 확인 없이 백업은 백업이 아닙니다          |

## 7단계 — 운영 규칙 (정하고 공유하면 끝)

| #   | 규칙                                                               |
| --- | ------------------------------------------------------------------ |
| F1  | 입력 담당과 승인자를 분리한다 (시스템이 자기 승인을 이미 막습니다) |

| F4  | 월 마감을 다음 달 5일까지로 못 박는다                              |
| F6  | 급여 실액은 시스템에만 둔다                                        |
| F7  | 판정 대기 건에 기한을 정한다 (예: 3영업일)                         |

## 값이 오면 제가 하는 것

| 대표님이 주시는 것    | 제가 하는 것                                  |
| --------------------- | --------------------------------------------- |
| `DATABASE_URL` 넣었다 | `db:push` → 시드 적재 → V1~V8 검증 리포트     |
| `CRON_SECRET` 넣었다  | 알림 크론 동작 확인 (지금은 하루 1회)         |
| 슬랙 4개 넣었다       | 수집·발송 실제 확인                           |
| 기업은행 컬럼 머리글  | 파서를 실제 양식에 맞춤 — 대사 로직은 그대로  |
| 세율·기준금액 확인    | 코드 상수를 설정값으로 이전                   |
| 배부 기준             | 공통비 실제 배부 (지금은 전사 합계로만)       |
| 홈택스 자격증명       | 세금계산서 자동 수집                          |
| 「이메일로 간다」     | 이메일 발송 어댑터 (30분)                     |
| 실제 숫자 다 넣으셨다 | 여신·계좌·예산 화면을 실제 데이터로 다시 검증 |
