# 맥에서 쓰기

## 설치 (한 번만)

터미널에 `bash ` 를 치고 **이 폴더의 `setup.sh` 를 터미널 창으로 드래그**한 뒤 엔터.
자세한 안내는 프로젝트 폴더의 `설치방법.txt`.

`setup.sh` 가 하는 일:

1. macOS 격리 속성 제거 — 인터넷에서 받은 파일이 실행되지 않는 원인
2. `~/.work-recorder/venv` 에 설치 (시스템 파이썬은 건드리지 않음)
3. `.env` 생성 + API 토큰 자동 생성
4. **`~/Applications/업무녹음.app` 생성** — 이 컴퓨터에서 만든 앱이라 Gatekeeper가
   막지 않는다. 로그인 시 자동 실행으로도 등록한다
5. 가짜 녹음 1건으로 전체 흐름을 돌려서 확인

다시 실행해도 안전하다. `.env` 는 덮어쓰지 않는다.

## 메뉴바 앱

앱을 실행하면 화면 맨 위 상태바에 아이콘이 생긴다. Dock에는 뜨지 않는다
(`LSUIElement`).

| 아이콘 | 상태 |
|---|---|
| 🎙 | 대기 중 |
| 🔴 | 녹음 중 (경과 시간과 파일 수 표시) |
| ⚠️ | 업로드 실패 — 점검이 필요함 |

메뉴:

| 항목 | 하는 일 |
|---|---|
| ● 녹음 시작 / ■ 녹음 종료 | 30분 단위로 나눠 `~/업무녹음` 에 기록 |
| 오늘 녹음 정리하기 | 작업 큐에 넣고 접수 → 진행 → 완료를 메뉴에 표시 |
| 자동 정리: 매일 00:05 | 앱이 켜져 있으면 스케줄러가 함께 돈다 (표시 전용) |
| 녹음 폴더 열기 / 설정 열기 | Finder·편집기로 연다 |
| 점검하기 | 마이크, 저장소, 업로드 대기, 최근 정리 결과, 설정 문제 |

**서버를 따로 띄울 필요가 없다.** 앱 안에서 워커와 스케줄러가 함께 돈다.

## 기존 앱에서 고친 것

| 문제 (KNOWN_ISSUES) | 이번 구현 |
|---|---|
| LaunchAgent로 띄우면 메뉴바 아이콘이 안 보임 | `.app` 번들로 실행. 마이크 권한도 이 앱 하나에만 물으므로 실행 주체가 바뀌어 권한이 꼬이지 않는다 |
| 청크 프레임을 메모리에 쌓은 뒤 저장 | 받는 즉시 디스크에 기록. 8시간 녹음에도 메모리 사용량이 일정하다 |
| 세션 종료 후 일괄 업로드 | 청크가 닫히는 즉시 업로드. 실패하면 재시도 큐에 남고, 앱을 껐다 켜도 목록이 유지된다 |
| `지금 바로 정리하기`의 접수 시점이 불명확 | 작업 큐에 직접 넣고 접수·진행·완료를 메뉴에 표시 |
| 자정 실행이 외부 스케줄러에 의존 | 앱이 켜져 있으면 스케줄러가 함께 돈다 |
| 무음 감지로 파일이 사라짐 | 임계값으로 버리지 않는다. 품질 경고는 분석 단계에서 남긴다 |
| 자정을 넘긴 녹음이 두 날짜로 쪼개짐 | 업무일은 **세션 시작 시각** 기준으로 고정 |

전역 단축키(`Option+Shift+R`)는 넣지 않았다. 입력 모니터링 권한이 필요해 실패
사례가 많았고, 메뉴바 조작으로 대체된다.

## 녹음 파일은 어디로 가나

`~/업무녹음` (설정의 `LOCAL_SOURCE_DIR`). `SOURCE_ADAPTER=google_drive` 로 두면
청크가 닫히는 즉시 Drive에도 올라가며, 이때 `appProperties.business_date` 를 함께
기록하므로 자정 전후 파일이 엉뚱한 날짜로 묶이지 않는다.

원본은 자동으로 지우지 않는다.

## 단일 실행 파일이 필요하면

```bash
bash mac/build-binary.sh
```

`dist/work-recorder` (CLI) 하나가 나온다. 빌드는 반드시 맥에서 해야 한다
(PyInstaller는 크로스 컴파일 미지원).
